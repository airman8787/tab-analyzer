# タブ録音アナライザ

ブラウザで再生中の曲（Spotify・YouTube など）をタブから直接録音し、ラウドネス・ピーク・周波数バランス・ステレオ・構成などを数値化して、リファレンス曲と比較するツールです。HTML ファイル 1 つで動き、インストールは不要です。**音声はすべて PC 内で処理され、外部に送信されません。**

## すぐに使う

**https://airman8787.github.io/tab-analyzer/** をブラウザで開くだけで使えます（GitHub Pages）。ページはブラウザ内で動き、録音や解析した音声がサーバーに送られることはありません。

`tab-analyzer.html` をダウンロードして、ローカルで開いても同じように使えます（保存したリファレンスは、開いた場所ごとに別々に保存されます）。

## 使い方

1. ツールを Chrome または Edge（PC 版）で開きます。
2. 「録音開始」→ 共有ダイアログで **Chrome タブ** を選び、**「タブの音声も共有」** にチェックして共有します。
3. 曲を頭から再生し、終わったら「停止して分析」を押します。

音声ファイル（WAV / AIFF / FLAC / MP3 / Ogg / AAC など）をドロップして解析することもできます。ファイル解析はどのブラウザでも使えます。

> **タブ録音の音声は、解析のためにページ内で一時的に使うだけで、保存・書き出しはできません**（解析結果の数値は保存できます）。配信サービスの利用規約を守ってお使いください。

> タブ録音は配信サービスで正規化（音量調整）された後の音です。統合ラウドネスとピークの絶対値は元のマスターと一致しません。PLR・LRA・クレストファクタ・帯域バランスは正規化の影響を受けないので、比較にはこれらを使ってください。YouTube の「安定した音量」などの音量処理はオフにしてください。

## 主な機能

| 分類 | 内容 |
|---|---|
| ラウドネス | 統合・モーメンタリー・ショートターム（ITU-R BS.1770-4）、LRA（EBU Tech 3342）、トゥルーピーク、PLR、クレストファクタ |
| 公開前チェック | ジャンル別の目安・リファレンス・ターゲットに照らした判定を、重要度順に「対処のしかた」と「該当箇所の再生ボタン」つきで表示。音圧（最大ショートターム）× PSR の地図に、自分の曲と保存した曲を並べて表示 |
| ダイナミクス | PSR（3 秒窓のトゥルーピーク − ショートタームラウドネス）の推移と、曲の一番大きい区間の値・8 dB を下回る区間の検出。DR 値（TT DR Meter / DR14 互換） |
| ターゲット比較・マッチ EQ | 長時間平均スペクトル（1/6 オクターブ、静かな部分を除外）を、保存した複数の曲から作ったターゲット（中央値と 10〜90% のばらつき）と比較。重ねる／差だけ／4 帯域の表示。差を少数のピーキング・シェルフで近似した EQ を提案し、適用量を変えながら再生にかけて聴ける |
| 低域 | 120 Hz 以下のクレストファクタ（大きい区間）、サブ／キック・ベース／低中域のレベルをターゲット・リファレンスと比較 |
| 帯域の上限 | 高域が急に切れている周波数の検出（生成 AI の出力や、圧縮音源を経由した音の確認用） |
| 配信コーデック試聴 | WebCodecs で AAC（Windows・Mac）／ Opus に変換・復元し、相互相関で遅延を補正。変換後のトゥルーピークと 0 / −1 dBTP を超えた箇所、帯域ごとの波形の変化。元の音・変換後・差分を切り替えて試聴 |
| 構成 | 音色と和声の自己類似行列による区間推定、似た区間の分類（A/B/C…）、サビ候補の推定 |
| 比較 | 結果の保存（ブラウザ内）、曲全体／サビ区間での比較、音量を揃えた A/B 試聴（サビ同士の位置合わせ。リファレンスの音声は自分のファイルのみ） |
| 配信 | Spotify・Apple Music・YouTube・Amazon・TIDAL・Deezer での音量調整のプレビュー（目安）と、その音量での試聴 |
| 表示 | 波形、ラウドネス推移、スペクトログラム（FFT サイズ・窓・軸を設定可、PNG 保存）、ズーム、再生中のスペクトラム・ゴニオメーター |
| 選択範囲 | ドラッグで範囲選択 → スペクトラム（FFT 1024〜65536・窓 4 種）、ラウドネス・ピーク、ループ再生、書き出し、CSV 保存 |
| ステレオ | 相関・ステレオ幅（全体・帯域別・時間推移）、低域の相関、ゴニオメーター |
| ピッチ | YIN 法による基本周波数の推定、音域・チューニング・音程分布の分析（単音向け） |
| マルチチャンネル | 5.1ch / 7.1ch 等のファイル（LFE 除外・サラウンド重み付き、ステレオ系の指標はダウンミックス） |
| 騒音計・オクターブ | IEC 61672-1 の A / C / Z 特性と Fast / Slow（LAeq・LAFmax・LCpeak・LAE・LAF5〜95）、IEC 61260-1 の 1/1・1/3 オクターブ、音圧校正（校正器の音から自動設定可） |
| 心理音響 | ラウドネス ISO 532-1（Zwicker 法、定常・時間変動、sone / phon、特定ラウドネス）、シャープネス DIN 45692、トーナリティ ECMA-74（TNR / PR）、ラフネス・変動強度（モデルによる推定） |
| 編集・信号 | 再生にかける IIR フィルタ（3 段）、FIR / IIR で処理した音声の解析、信号発生（正弦波・スイープ・雑音・変調音など） |
| 回転機械・多チャンネル | 次数解析（タコ信号・音からの回転数推定・一定回転数、次数マップ・次数の切り出し）、伝達関数 H1 / H2・コヒーレンス、複数ファイルの一括処理と統計 |
| 表示・記録 | ウォーターフォール（3D）、マーカー、レポート（印刷して PDF 保存・HTML 保存） |
| 分離（AI なし） | 調波（持続音）／打楽器（アタック）の分離、センター（ボーカル寄り）の抽出・除去（カラオケ風）、3 帯域への分割。いずれも信号処理による分離で、AI による楽器ごとの分離より精度は下がります |
| 音符・MIDI | 和音を含む音符の検出とピアノロール表示（クリックでその位置を再生）、合成音での試聴、MIDI ファイルの保存（目安） |
| 修復 | 電源ハム（50 / 60 Hz を自動判定）・定常音の除去、背景雑音の低減（自動または選択範囲を手本に）、クリック・プチノイズの除去。取り除いた音だけを聴くこともできます |
| ピッチ・時間 | 音階への補正（単音向け、補正量・速さを指定、キーの推定値も使える）、ピッチシフト（±24 半音）、音程を変えないタイムストレッチ（25〜400%） |
| その他 | BPM・キー推定（目安）、自分の音声ファイル・信号発生の音の範囲書き出し（WAV 24bit / 32bit float、FLAC 24bit）、Claude 等に貼り付けられるテキスト要約 |

## 精度の検証

`verification/` に検証スクリプトがあります（Node.js で実行）。

```bash
node verification/ebu-synthetic.js       # EBU Tech 3341 / 3342 の正弦波ケース
node verification/truepeak-sine.js       # トゥルーピーク（理論値が分かる正弦波）
node verification/compare-reference.js   # 独立した参照実装との突き合わせ（WAV ファイルを引数で追加可）
node verification/nvh-checks.js          # 騒音計・オクターブ・心理音響・伝達関数・次数解析
node verification/diagnostics-checks.js  # PSR・DR・トーナルバランス・帯域上限・低域・マッチ EQ・位置合わせ
node verification/edit-checks.js         # 分離・修復・ピッチシフト・タイムストレッチ・音階補正・音符検出・MIDI
```

| 項目 | 結果 |
|---|---|
| EBU Tech 3341（1〜6・9・12）/ 3342（1〜4）を規格書どおりに生成した信号 | 17/17 合格（ラウドネスの差は最大 0.04 LU、LRA は期待値ちょうど） |
| トゥルーピーク（正弦波、44.1 / 48 / 96 kHz × 6 周波数 × 5 位相） | 90/90 が +0.2 / −0.4 dB 以内。0.01〜0.45 fs の全位相で誤差 ±0.0001 dB |
| 独立した参照実装（規格書の 48 kHz 係数、FFT による 16 倍補間）との比較 | 統合・LRA・最大 M / S の差は 0.04 LU 以内。実際の録音（44.1 kHz・約 4 分）では全項目差 0.00。トゥルーピークは通常の音源で 0.03 dB 以内 |

トゥルーピークは、BS.1770 の 4 倍補間フィルタでピーク候補を探し、その近くだけカイザー窓 sinc（±128 タップ）で 1/16 サンプル刻みに求め直しています。規格書に例示されたフィルタは fs/4 付近で最大 +0.22 dB 読み過ぎ、ナイキスト付近で約 2 dB 読み落とすため、その両方を補正するためです。

| 騒音計・オクターブ（IEC 61672-1 / 61260-1） | A / C 特性の規定式との差は 16 kHz まで 0.23 dB 以内。トーンバースト応答（Fast / Slow、2 ms〜1 s）は規定値との差 0.05 dB 以内。帯域中心の正弦波 ±0.06 dB、帯域境界 −3.0 dB |
| ラウドネス ISO 532-1 | 附属書 B.2 の試験信号 1 で 83.296 sone（期待値と一致）。1 kHz・60 dB は定常 4.07 / 時間変動 4.05 sone（期待 4.019、+1.2% 以内） |
| シャープネス・トーナリティ | DIN 45692 の基準音で 1.02 acum。ECMA-74 の TNR は解析解との差 0.3 dB 以内 |
| 伝達関数・次数解析 | H1 は理論特性との差 0.02 dB 以内。次数成分のレベルは 0.4 dB 以内 |
| PSR・DR | 正弦波の PSR は理論値（ステレオ 0 / モノラル 3.01 dB）と 0.01 dB 以内。任意の 3 秒窓を切り出して求めた値との差 0.15 dB 以内。DR は正弦波 0・矩形波 −3.01（理論値どおり）、素直な実装と完全一致 |
| 分離・修復 | 調波＋打楽器・3 帯域は足すと元に戻る（誤差 0.0001 以内）。左右に同じ音・片側だけの音のセンター抽出で 30 dB 以上分離。ハムは 50 / 60 Hz を判定し倍音を 40 dB 以上低減（音楽成分の変化 0.03 dB）。雑音は 12 dB 低減（音の変化 0.01 dB 以内）。クリックは 20 個すべて検出して誤差を 40 dB 以上低減、ドラム風のアタックは誤検出しない |
| ピッチ・時間・音符 | ピッチシフト（+12 / −5 / +0.5 半音）とタイムストレッチ（1.5 / 0.75 倍）の周波数誤差 3 セント以内・レベル差 1 dB 以内。音階補正は 450 Hz → 440 Hz（誤差 1 セント以内）。単独の音・和音（合成したピアノ風の音 8 個）は全て検出し立ち上がり誤差 6 ms。ドラム・ボーカル入りの混ざった音では和音・ベースの検出は 24 個中 10 個程度（目安） |
| トーナルバランス・帯域上限・マッチ EQ | ピンク雑音で 40 Hz〜16 kHz が平坦（±0.6 dB）、白色雑音の傾き +3.05 dB/oct（理論 +3.01）。16 / 19 kHz で切った雑音の上限を ±300 Hz で検出、なだらかな減衰は誤検出しない。既知の 4 段 EQ を残差 0.25 dB RMS で再現 |

ラウドネスの数表（ISO 532-1）は、公開されている実装 [MoSQITo](https://github.com/Eomys/MoSQITo)（Apache-2.0）の値と照合し、計算部分は独自に実装しています。**ラフネス・変動強度は、臨界帯域ごとの包絡の変調から求めるモデルの推定値で、規格（ECMA-418-2 など）の計算ではありません**（1 kHz・60 dB・100% 変調で 70 Hz → 1 asper、4 Hz → 1 vacil に校正）。

**EBU の公式テストファイル（実際の番組音声・公式トゥルーピーク試験信号）による準拠試験は実施していません。** そのため「EBU 準拠」とは称していません。

## 制約

- タブ録音は Chrome / Edge（PC 版）のみ。録音は最大 10 分。
- キー・BPM・構成・ピッチの推定は目安です。ピッチ解析は単音向けで、伴奏のある曲では誤検出が混ざります。
- 配信サービスの音量調整は、各社の公表値や一般的な報告に基づく目安です。
- PSR の目安（8 dB）や DR 値の解釈は、エンジニアの経験則で規格値ではありません。「汎用の目安」ターゲットは公開研究の平均的な傾きから作った大まかな基準で、ジャンル別の基準は自分で保存した曲から作る方式です。
- コーデック試聴はブラウザ内蔵の変換器を使うため、各配信サービスの実際の変換とは同じではありません。Chrome の AAC は Windows・Mac のみ（Linux 不可）で、ビットレートは最大 192 kbps です。「波形の変化」は音質の評価値ではありません。
- タブ録音の音声は保存できません。10. で分離・修復・ピッチ編集した音も同じです。A/B 試聴用に音声を保存できるのは、自分の音声ファイルと信号発生の音だけです。
- 10. の分離は AI を使わない信号処理です。音符の検出は、オクターブで重なった音・減衰した音・打楽器の多い曲で取りこぼしや誤検出が出ます。音階への補正は歌・単音の楽器向けで、和音には使えません。ピッチシフトはフォルマントも一緒に動きます。
- 保存したリファレンス（数値・音声）はそのブラウザ内にのみ保存されます。数値は JSON で書き出せますが、音声は含まれません。
